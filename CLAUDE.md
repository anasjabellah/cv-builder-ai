# CLAUDE.md

## 1. Project Overview
**What this project does**: 
A Next.js web application that converts outdated resumes/CVs (PDF/Word) into professionally designed HTML resumes using AI. Users can upload documents, AI extracts content, customize formatting, and export polished resumes in PDF/Word formats.

**Target Users**: 
Job seekers needing to modernize old resumes, HR professionals looking for professional CVs, and remote workers requiring formatted documents.

**Core Features**: 
- AI-powered extraction of CV data (Names, experience, skills) via Groq API 
- Manual editing of extracted data with rich text fields 
- 3 AI-generated design styles (Modern, Classic, Creative) using OpenAI GPT-4o 
- Export options: PDF (via Printer) and DOCX 
- Firebase authentication for user accounts 
- Form validation and error handling

## 4. Architecture & Data Flow
**Parsing Flow**
1. User uploads a PDF or Word document via the Upload component. 
2. `POST /api/parse-cv` receives the multipart request. 
3. The route validates allowed MIME types (`application/pdf`, DOCX, MS Word). 
4. The file is read into a Buffer and handed to `extractCV` (located in `src/lib/extract-cv`). 
5. `extractCV` contacts the Groq API to extract structured resume data (personal info, experience, education, skills, etc.). 
6. The server returns `{ formData: <structured data> }` which populates the client editor.

**Generation Flow**
1. After editing, the user selects a style (modern, classic, creative). 
2. `POST /api/generate-cv` receives `{ formData, style }`. 
3. The route invokes `generateCV` (in `src/lib/generate-cv`). 
4. `generateCV` calls OpenAI's GPT‑4o (or another model) to produce HTML formatted according to the chosen style. 
5. The server returns `{ html }`. 
6. The client renders the HTML preview and offers export options (PDF via Puppeteer, DOCX via `html-to-docx`).

## 5. Setup & Installation
**Prerequisites**
- Node.js ≥ 18
- Access to Groq API (free key)
- Access to OpenAI API (GPT‑4o key)
- Firebase project (enable Google Auth + Firestore)

**Installation Steps**
```bash
# Clone repo
git clone https://github.com/anasjabellah/cv-builder-ai.git
cd cv-builder-ai

# Install deps
npm install

# Create .env (based on .env.example)
cp .env.example .env
# Edit .env and paste your API keys

# Run dev server
npm run dev
```
Open `http://localhost:3000`.

## 6. API Documentation
### `POST /api/parse-cv`
**Request**: multipart/form-data with a single field `file` (PDF, DOCX, or Word). 
**Responses**:
- `200` – `{ "formData": <CVFormData> }`
- `400` – `{ "error": "No file provided" }` or unsupported MIME type message.
- `500` – `{ "error": <error‑message> }`

### `POST /api/generate-cv`
**Request**: JSON payload
```json
{
  "formData": { /* full CVFormData object */ },
  "style": "modern" | "classic" | "creative"
}
```
**Responses**:
- `200` – `{ "html": "<generated‑html>" }`
- `400` – missing data error
- `500` – server error with message

## 7. Development Guidelines
- **TypeScript strict mode** – all new code must conform to the existing interfaces in `src/types`. 
- **Tailwind** – utilities defined in `tailwind.config.js`; prefer utility classes over custom CSS. 
- **API routes** – keep logic thin; delegate heavy work to functions in `src/lib`. 
- **Adding new features**: create a new lib function, expose it via an API route, and add a UI component that consumes the endpoint. Update the corresponding types.
- **Testing**: currently no test framework is configured. Add Jest + `ts-jest` and write unit tests for `extractCV` and `generateCV` to guard against regression.
- **Linting**: run `npm run lint` (uses Next.js built‑in ESLint).

## 8. Known Issues & TODO
- **Missing test suite** – adding Jest is a high priority. 
- **Export limitations** – PDF export currently relies on browser print; a dedicated Puppeteer service could improve reliability. 
- **AI token limits** – large CVs may exceed request size for Groq/OpenAI; consider chunking. 
- **Styling customization** – only three preset styles; future work could expose theme variables to users. 
- **Error handling** – UI currently shows generic messages; should surface more detailed validation errors.
